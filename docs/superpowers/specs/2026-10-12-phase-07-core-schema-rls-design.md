# Phase 07 Core Schema and RLS — Bounded Design

**Status:** Owner approved continuing with the bounded Phase 07 foundation after the Phase 04 smoke follow-up; this document is for owner review before implementation planning. **Decision:** ADR-77. **Base:** `main` after PR #15; draft PR #16 is a separate Phase 04 documentation follow-up and is not a dependency.

## Boundary and alternatives

Phase 07 contains five sittings. This design covers the first vertical schema/security slice, **not** the entire phase. Existing migration `0001_identity_and_access.sql` already owns `users`, `plans`, `plan_member_aliases`, `plan_members`, invites, and membership RPCs with forced RLS. The encrypted `AppDatabase` currently has schema version 1 and no persistent application tables. A plan setup UI still keeps its partial SCR-03 inputs only in account-bound session memory (ADR-75); this sitting must not persist that draft or call `create_plan`.

We considered (1) one migration for every Phase 07 entity, (2) local-only Drift tables, and (3) a reviewed core vertical slice. Choose **(3)**: add ledger and immutable log to the synthetic-local server and mirror plans/identity, ledger, log, and device state locally, with their authorization and migration tests in the same slice. (1) makes a large coupled schema hard to review before repositories exist; (2) would defer the most important authorization boundary. The missing Phase 07 entities and writer remain explicit follow-up sittings, not silent omissions.

## Server boundary: local development only

Add an additive `0002` migration, never rewrite `0001`. It introduces `public.ledger_entries` and `public.change_log` keyed to existing plans. Every row has a non-null `plan_id` and a client-supplied UUID; log rows include `schema_version`, typed JSON old/new values (including JSON null distinct from absent), device UUID, nonnegative monotonic counter, stable `plan_member_id`, nullable pre-acceptance `server_ts`, `created_at`, and optional group ID. Enforce the composite `(plan_id, plan_member_id)` alias reference so an alias from another plan cannot author an event. Enforce sensible positive schema version and row shape, but do not invent a sync protocol or server order allocator in this sitting. An immutable-log trigger rejects update/delete even for a privileged writer; only a future authenticated sync transaction can insert an accepted row and assign its timestamp at insert.

`ledger_entries` stores only source fields from `design.md` §4.4: plan, six-category code, `standard` or an existing hidden-fee subtype, nonblank supplier (at most 200 characters), mandatory nonnegative flat estimate or **null** per-head estimate, nullable nonnegative actual in signed int64 centavos, `per_head`/`flat` mode, nonnegative per-head rate required only in per-head mode, `manually_valued`, notes (max 2,000 characters), optional template/checklist provenance, and created/deleted timestamps. Mode, estimate and rate must be coherent per REQ-LG-1 clauses 2–4. Enforce six known category codes locally, not a fake remote ruleset table: ADR-15's ruleset remains a bundled, immutable JSON asset. Do not seed benchmark costs, fees, supplier rows, region rules, or a ruleset version. The existing `plans` region/ruleset fields are not retrofitted with an impossible FK to unpublished remote tables in this slice. Derived effective amount, payment status, deposit, conflict/superseded flag, allocator result, and export artifact are not columns.

Enable **and force** RLS on each new plan-scoped server table. A read policy for an authenticated live member uses the existing `identity_member(plan_id)` predicate; an alias alone grants nothing. Revoke direct insert/update/delete from `anon` and `authenticated` regardless of RLS. Permit only controlled trusted-server fixture insertion in disposable synthetic tests; do not grant client mutation merely to make a test pass. A removal of a membership must stop future reads. Inventory all existing and new plan-scoped tables on every schema change; a newly introduced plan table lacking forced RLS or a membership policy fails a blocking local/CI test. No migration runs on hosted Singapore staging, Tokyo, or production under ADR-76.

## Encrypted local boundary

Advance `AppDatabase` from v1 to v2 with matching typed Drift tables for the existing plan and live identity/alias shape, plus `ledger_entries` and raw `change_log`. Add local per-device/per-plan sync state and a pending-event outbox keyed to log IDs, but **no queue producer or network consumer** yet. Store the log's JSON payload losslessly, including unknown compatible additive rows for Phase 08; never infer meaning from unknown rows or write repair values. Match server IDs, money and relevant constraints; use SQLite integer for cents/counters and explicit nullable columns. Referential links guard plan/alias and outbox/event identity. Local reads and schema migration must not invoke a network request. Continue using the existing `EncryptedDatabaseOpener` and its fail-closed key/cipher behavior; do not add a plaintext executor in production.

Migration v1→v2 is atomic. v1 had no application or queued rows; preserve any unrelated SQLite data and the encryption key rather than resetting files. Reopen encrypted v2 data and prove exact centavos, alias/plan IDs, log payload bytes, and pending-event identity survive; failed upgrades must leave the previous readable DB/queue intact. There is no v2→v1 down-migration for real devices: a lower-version binary detects the newer schema and fails before partial writes. Future schema upgrades must test nonempty queues explicitly. No identity screen, plan-creation behavior, or full repository API changes in this sitting.

## Evidence and failure behavior

Use TDD per vertical behavior. On a **disposable synthetic local** Supabase instance with `0001` then `0002`, create two verified synthetic accounts and separate plans via existing RPCs; seed distinguishable ledger/log rows through a trusted test-only path, then exercise direct REST as each account. Assert own read works; foreign-plan and nonexistent-plan read/list are indistinguishable; forged plan/alias associations and direct insert/update/delete fail; a removed member loses access; and a privileged log update/delete fails via the immutability trigger. Inspect `pg_class` plus policy catalog for all current plan-scoped tables, not merely names in a hand-written allowlist. Never mark the full TC-SEC-01/04/05/06 or TC-API-05 suite PASS when future tables/sync paths are absent; label the exact covered subset. Add this executable subset to the blocking tenant-isolation CI job, noting that current GitHub jobs can fail before executing steps and local green is not remote CI green.

Test a version-1 encrypted DB upgrade to v2, reopen, precise 64-bit centavo/log JSON/outbox round-trip and fail-closed newer-version opening; retain existing Phase 05 encryption tests. Test SQLite constraints with two synthetic plans and no app network. Use a fresh disposable local stack for reset/backward tests; never run a destructive reset against retained local Supabase volumes. A migration or policy failure aborts the sitting rather than downgrading encryption or relaxing RLS. Update the Phase 07 evidence ledger, policy inventory and privacy-data inventory for supplier names, notes and log old/new payloads, with no claim that shared-record erasure is solved (OQ-01).

## Scope gates and exit

This slice is demonstrably deterministic and explainable: it stores typed user inputs and an attributable immutable record, not predictions. It initiates **no money movement** and **no supplier recommendation**; v1 remains non-AI. All currency is signed int64 centavos; ratios (when later added) use basis points, never floating point. No invented fee, price, legal checklist timing, or benchmark fills OQ-04/11. No real-couple data, hosted migration, Pro billing, production approval, sync transport, writer transaction, checklist/guest/pledge/payment tables, or complete Phase 07 certification follows. ADR-64/72/76 and OQ-07/DPO/counsel, tenant-isolation, beta and physical-device gates remain open.

The implementation sitting exits only when the new schema/policy/negative and migration tests run locally without skips, the existing Flutter suite and analysis pass, the changed-file secret scan and Git diff checks are clean, and a draft PR to `main` explicitly lists deferred Phase 07 coverage and remote CI status. This spec/ADR commit itself establishes **design scope only**, not any test PASS.
