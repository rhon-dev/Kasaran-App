# Phase 07 Local Ledger Repository and Atomic Writer — Bounded Design

**Status:** Owner approved the local-only design on 2026-10-14 and reviewed the written spec. **Decision:** ADR-78. **Dependency:** PR #18 (`feat/phase-07-core-schema`) is merged and supplies encrypted Drift v2 tables, local Supabase RLS tests, and the append-only server log. The local writer follow-up lives on `feat/phase-07-ledger-writer`; the earlier GitHub Actions billing lock is not a passing CI gate.

## Boundary and alternatives

Phase 07 still needs the remaining entity schema, repositories, transactional writers, migration matrix, and full tenant tests. Three sequences were considered: (1) add every remaining entity and writer at once; (2) jump to Phase 08 transport with no local queue producer; (3) add a local ledger repository and atomic ledger event writer against the existing v2 schema. The owner chose **(3)**. It can be tested offline end-to-end without paying for infrastructure or pretending that incomplete server entities and sync already work. The ledger slice is not completion of Phase 07, REQ-SE-4, TC-MIG-01…03, or the full TC-SE-26.

## Responsibilities and interfaces

- `data/repositories/ledger_repository.dart` exposes typed, plan-scoped local reads of live entries and explicit create/edit/delete methods. It depends only on `AppDatabase` and a local writer, never on an HTTP client or hosted service. A read returns persisted source fields, not a payment status, computed effective price, or inferred ruleset data. Deleted entries are excluded from the live list but retained in the database/history.
- `data/changelog/local_ledger_writer.dart` owns the single transaction for each accepted edit. Inputs carry current `plan_id`, authenticated local `user_id`, stable `plan_member_id`, `device_id`, and a validated ledger command. The writer checks the supplied actor against a required, trusted `VerifiedLocalIdentity` adapter reading the current verified Auth session, then checks a matching local plan, live membership and alias for that same user and plan; a caller-provided valid tuple for a different signed-in account fails closed. The writer captures an opaque verified-session marker, rechecks it after membership lookup and before returning from the local transaction, and rolls back when it changes before that check (including A→B→A); the read path also rechecks after its transaction completes before returning rows. The repository refuses a writer bound to a different database. **Known development limitation:** a session can change after the writer's final check while the database commit is still pending; this slice does not serialize Auth transitions with database commits and must not claim absolute cross-account commit isolation. A later bounded integration must coordinate Auth transition and writer lifecycle before phase exit or real use. These are checks on the **last known local membership**, not an authorization claim about a remote revoked session; Phase 08 must recheck on server acceptance. Invalid or cross-plan references fail with no partial state. The repository is the only exposed application write path for these rows.
- An injectable UUIDv7 ID source and UTC clock make generated IDs/timestamps deterministic in tests; production uses cryptographic randomness for IDs. Do not use wall-clock time as a conflict-ordering key. Use the existing `sync_state(device_id,plan_id)` monotonic counter. Initialize it on first write, increment once per emitted event inside the transaction, and reject overflow. Do not alter a pull cursor or assign `server_ts`; both remain Phase 08 responsibilities.
- One database transaction validates the input, mutates the ledger projection, appends immutable **event content** to `change_log`, and inserts the matching `outbox` row. A unique-event-ID collision, invalid foreign key, constraint error, or lost key aborts the transaction; neither projection, log, outbox, nor device counter advances. Do not expose an update/delete method for historical events. Local `server_ts` may later be assigned on acknowledgement; this slice does not add a blanket SQL trigger that would block that Phase 08 operation. The server log remains protected by its existing immutable trigger and forced RLS.

## Event contract

1. **Create:** One `$create` event contains the full validated initial `ledger_entries` snapshot (parent plan ID, canonical UUIDv7 ID, category/subtype, supplier, mode, integer-centavo source fields including explicit nulls, provenance, and timestamps). `old_value` encodes JSON null; `new_value` encodes the complete typed snapshot. Insert the projection and one queued event atomically. Do not create a zero-price placeholder from a template, fee prompt, or checklist suggestion.
2. **Independent edit:** For each changed ordinary source field (such as supplier, notes, category, actual amount), append one event with typed old/new JSON values, including explicit null. Unchanged fields emit nothing. Validate the entire resulting row, not just the edited field; multiple fields in one accepted command share one transaction, with one increasing counter value and one outbox row per event. Reject edits to an already tombstoned row.
3. **Pricing-mode edit:** `(pricing_mode, per_head_rate_cents)` is one indivisible group. Emit exactly one event with `field_name='pricing_mode'`, a fresh non-null `change_group_id`, and complete typed old/new group snapshots, including the unchanged or null member. The same local transaction updates the projection's coherent flat estimate/per-head rate fields; when a mode switch also changes `estimated_cents`, emit its separate ordinary field event in that transaction. This is **local** atomicity only: Phase 08 must specify/test server acceptance of the related events and post-merge invalid-value gating rather than claim that two network events are already atomic. Never split mode and rate into separate events. A flat entry has a nonnegative `estimated_cents` and null rate; a per-head entry has null estimate and a nonnegative rate. No per-head derived total is stored.
4. **Delete:** Set `deleted_at` instead of deleting the projection. Emit one `deleted_at` event with typed JSON null old value and UTC timestamp new value; retain the row, event history, and pending queue. Repeated deletion of the same row is a no-op. Restore and remote tombstone replay are later slices, not implicit resurrection here.
5. Every event has an independent client UUIDv7 ID, `entity_type='ledger_entries'`, matching `plan_id`/`entity_id`/`plan_member_id`/`device_id`, `schema_version=1` for this event payload format (distinct from Drift file version 2), null `server_ts`, increasing `device_monotonic`, and an outbox row with the same `event_id`, plan, and device. Serialize generated JSON deterministically and preserve raw text on reopen. Do not store derived conflict/superseded flags.

## Validation and evidence

- Money is signed int64 **integer centavos**; ratios, if later needed, are integer basis points. Reject invalid category/subtype, blank or overlong supplier, negative cents, incompatible flat/per-head mode fields, overlong notes, nonexistent plan, foreign alias, missing live membership, and a mismatched plan on update/delete. The six hidden-fee subtypes use `design.md` §4.4’s fixed category mapping. Until a same-plan checklist repository and pinned template-catalog validator exist, fail closed on non-null `checklist_item_id` or `template_suggestion_id`; never accept unchecked or foreign provenance. A local read likewise requires the last-known plan/member/alias match. Do not fabricate prices, fees, benchmarks, supplier recommendations, or legal checklist dates.
- Use test-first encrypted-database integration cases: create then reopen with exact cents, typed event JSON and pending outbox; independent fields and group snapshots; tombstone/no-op behavior; a deliberate late constraint or event-ID failure that proves complete rollback of projection/log/outbox/counter; foreign-plan and revoked-local-membership rejection; and an offline read/write test that fails if any HTTP client is created. Run the service-free unit selector **with Supabase stopped**, analyzer, and the full Flutter suite against the existing disposable local stack if contract/isolation tests are included. Count skips separately.
- Preserve the prior local and server schemas; if a schema change proves necessary, write an additive migration and tests before changing it. No hosted migration, network push/pull, real-couple data, paid upgrade, new UI, production readiness, or full security verdict follows from this slice. The existing Free Singapore synthetic project and Tokyo project remain untouched.
- This v1 work is deterministic (validated inputs and ordered local counters), explainable (attributed typed events and source values), moves no money (records budgets only), and recommends no supplier (stores a couple-entered name only). It adds no AI.
