# Phase 07 account-scoped encrypted local store (ADR-79)

**Status:** Owner approved the architecture and reviewed this written design. Design only; not implemented. This is a prerequisite for accepting ADR-78's ledger writer and for Phase 07 exit, not Phase 08 work.

## Problem and invariant

ADR-78's writer checks an opaque verified-session marker immediately before its Drift transaction callback returns. Drift may complete the COMMIT asynchronously after that check. A verified A-to-B account switch can therefore occur while A's write is committing. The check cannot guarantee that a write is rolled back after the final callback check. The current encrypted file and key are device-global, and `LocalStoreBootstrap` opens that file before Supabase Auth initializes. A repository check alone cannot prevent another direct local reader or retained UI state from exposing the shared file.

**Privacy invariant:** Account B's local scope must never open or display A-only data or push A's queued events. A write already admitted for A may finish during an externally initiated switch, but only inside A's encrypted store; B's scope remains unavailable until the old scope is closed. App-initiated sign-out/sign-in waits for admitted operations to settle before changing Auth state. Server acceptance still requires fresh membership and attribution checks; local membership is last-known evidence only. This is not a guarantee that an already admitted A write can be canceled after database COMMIT starts.

## Boundaries and ownership

1. **Account store registry.** Resolve a verified Auth user ID to an opaque, stable account-store identifier in secure local metadata. Use a protected app-support subdirectory, an independently generated random encryption key per account in device secure storage, and `EncryptedDatabaseOpener`'s existing cipher/version checks. Do not put raw user IDs, session objects, tokens, or secrets in paths/logs. Existing shared file and key remain untouched as a legacy source until migration is completely verified; never use a missing key as permission to create a replacement for an existing file. Preserve iOS protection/backup exclusion and Android backup/device-lock checks for every new file. Signed-out, unverified and unknown identity have **no** open financial store.
2. **Lifecycle coordinator.** Initialize Auth before selecting a financial store. Mount sign-in routes without a store; mount plan/ledger routes only after a verified session and matching account store are ready. One coordinator owns the current account store, generation and operation leases. Ledger repositories/writers receive a lease-bound account handle, not an arbitrary process-global `AppDatabase`; they reject a stale generation. An app-initiated Auth transition first blocks new operations and protected routes, drains admitted operations including database COMMIT, closes the old store, and only then invokes Auth sign-out/sign-in. On observing a spontaneous SDK session event, the coordinator blocks protected routes before exposing any new account scope; it cannot retroactively stop an A COMMIT but must drain/close A before opening B. Revalidate the current verified session at each new lease and before mounting account-bound UI, rather than relying only on a stream callback. A-to-B-to-A gets a new generation each time. Dispose account-specific providers, dialogs/drafts and subscriptions on any identity change, including unknown/loading/error. Never present old rows while opening, failing, or migrating a store.
3. **Legacy migration without guessing ownership.** Treat the existing `kasaran.sqlite` plus its secure-store key as a sealed, recoverable source. Only inspect it after a verified account is established and its original key is available. Copy a plan's projections and required member/alias/history rows into that account's new encrypted store only when the legacy plan contains an unambiguous live membership for that account. Preserve full raw event JSON, exact integer centavos, tombstones, counters and pull cursor as data; do not mint events or change attribution. A pending outbox event belongs in the destination queue only if its `change_log.plan_member_id` resolves uniquely through that plan's alias to the current verified user. Partner-authored pending events remain sealed in the legacy source for that partner's later migration, even when the plan is shared; they must never be submitted from the other account's store. Unknown/null/conflicting aliases, inconsistent foreign keys, conflicting destination IDs, and unverifiable membership block promotion of affected rows and keep the legacy file intact. Do not silently pick a survivor, discard unknown schema/version payloads, or delete the legacy file. A staged copy plus validation/atomic promotion marker prevents a crash from exposing half-migrated state; retries are idempotent. A blocked migration shows an unavailable-store recovery state, not an empty new plan. The exact SQLite copy/secure-storage protocol belongs in the implementation plan and must be proven by a crash/reopen test before use.
4. **Store access and future sync.** All financial readers, writers, export builders and Phase 08 queue workers consume the currently leased account handle. Do not allow a raw global DB bypass for application code. A queued event carries its original plan/member/device attribution; Phase 08 must authenticate the current account, verify live membership on the server and reject an event whose resolved author is another account. Do not deploy hosted migrations/functions or use real-couple data in this slice.

## Failure behavior and tests

- Deterministic test pauses a write after its final session check but before COMMIT resolution. An app-controlled transition waits until COMMIT finishes; a spontaneous Auth replacement hides protected UI immediately and B's store never contains or returns A-only rows/events. A's encrypted reopen preserves the accepted queue. Repeat for A-to-B-to-A and an in-flight read.
- Build an encrypted legacy v2 fixture with an A-only plan, a shared A/B plan, exact centavos, raw unknown event payload, pending A and B events, a tombstone, and device/cursor state. Migrate as A then B, asserting own memberships, no foreign queue submission, unchanged source bytes, stable IDs and lossless reopen. A valid shared plan may appear in both account stores; outbox authorship must not duplicate. Test missing original/new key, inconsistent alias, conflicting IDs, unsupported future schema, interrupted copy and resumed migration; each failure keeps the legacy file recoverable and prevents incomplete financial UI.
- Test production app bootstrap/router on signed-out, unverified, loading, failed identity, sign-out, A-to-B and A-to-B-to-A transitions. Audit dialogs, exports and all direct DB readers. No account data renders until the matching scoped store opens; stale handles fail. A test using the real GoTrue adapter or an SDK-compatible local harness must verify session-object replacement, not only a fake identity marker.
- Run service-free analyzer/tests with local Supabase stopped, encrypted old-file migration/reopen and representative queued-write tests, then independently review account isolation and transaction-switch behavior. Disposable synthetic service-backed tests may be run later; local passes alone do not certify tenant isolation, Phase 07 exit, Phase 08, real-user or production readiness.

## Scope and four v1 tests

No new price, benchmark, fee, legal deadline, supplier suggestion, AI inference or money movement is added. Account selection and migration are deterministic (verified identity and attributable rows), explainable (blocked ownership is explicit), move no money and recommend no supplier. This design does not alter ADR-76's Free synthetic-only staging boundary or resolve OQ-07/DPO/counsel and beta gates.
