# Phase 07 Account-Scoped Local Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enforce ADR-79 account isolation across encrypted local storage, Auth transitions, and lossless legacy migration before accepting ADR-78's writer.

**Architecture:** Auth initializes before any financial database is opened. A secure account registry selects an opaque per-account file/key; a single lifecycle coordinator grants generation-bound operation leases, drains admitted Drift futures through COMMIT, and gates protected UI. A read-only legacy source is copied into a separately encrypted staged account store, validated and atomically promoted only with attributable membership/outbox rows; no fallback to a shared global database.

**Tech Stack:** Flutter/Dart SDK ^3.11.4, Riverpod ^3.3.2, go_router ^17.5.0, Drift 2.35.1, sqlite3 3.5.0 with sqlite3mc, flutter_secure_storage 11.2.0, flutter_test. Local schema is v2; event `schema_version` is distinct.

## Global Constraints

- ADR-79 privacy invariant: B never opens/displays A-only rows or submits A's pending events. An A write admitted before an external switch may COMMIT only to A's file; an app-controlled transition waits for the write's entire transaction future before invoking Auth.
- Auth must initialize before financial store selection. Signed-out, unverified, unknown/loading/error identity has no financial store; re-read the verified current session synchronously on each admission and before presenting account UI, not only from a status stream.
- Legacy `kasaran.sqlite` and `kasaran.local_db.v1` are recoverable, immutable sources; missing keys, unsupported schema, ambiguous ownership, conflicts or partial copy block financial UI. No reset, plaintext fallback, guessed survivor, minted events, loss of raw JSON/centavos/tombstones/counters/cursor, or deletion of the source.
- Keep iOS file protection/backup exclusion and Android device-lock/warning checks; random independent account keys live in device secure storage. No raw user IDs or secrets in paths/logs.
- Preserve current uncommitted ADR-78 reviewer changes and reconcile them with Task 2. Review the combined diff and commit related writer changes together only after security approval; do not silently stage unrelated files. No hosted actions, real-couple data, new prices, recommendations or financial movements; Phase 08 server membership/author validation is a separate gate.
- This document is a plan, **not** executed tests or an implementation. Commands below are future red/green acceptance steps; expected failures/passes are predictions, not observed results.

### Task 2: Generation-bound lease and post-check/pre-COMMIT race

**Files:** Create `lib/platform/db/account_store_coordinator.dart`, `test/platform/db/account_store_coordinator_test.dart`; modify `lib/data/changelog/local_ledger_writer.dart`, `lib/data/repositories/ledger_repository.dart`, `test/data/repositories/ledger_repository_test.dart`, `lib/data/changelog/verified_local_identity.dart` only if snapshot interface needs exposing the same synchronous source.

**Interfaces:** `AccountStoreCoordinator(VerifiedLocalIdentity identity, Future<AppDatabase> Function(VerifiedSessionSnapshot session) openAccount)` exposes `Future<T> withAccount<T>(Future<T> Function(AccountLease lease) operation)` and `Future<void> transition(Future<void> Function() changeAuth)`; `AccountLease` exposes immutable `userId`, `generation`, `Future<T> run<T>(Future<T> Function(AppDatabase db) work)` but not a freely retainable DB. The only DB capability is inside `run`, and `run` must synchronously reject stale generation/closed scope or mismatched current verified user. Coordinator's `observeSession()` handles externally changed Auth: immediately publish blocked state, invalidate generation, await in-flight leases, close old DB, then open the current verified account only if identity still matches; A→B→A must increment generation twice. `transition` blocks admissions/routes, drains `run` futures including Drift's asynchronous COMMIT, closes DB, **then** calls `changeAuth`, and re-opens if a newly verified session exists. Serialize concurrent open/close/transition using one future/mutex chain; never await a drain while holding a lease itself.

## Self-review against ADR-79

- Registry/key/file protection: Task 1; admission and asynchronous COMMIT drain: Task 2; immutable legacy source, shared plan and original-author outbox routing, atomic promotion/crash/reopen: Task 3; Auth-first signed-out and error/UI gating plus real SDK session replacement: Task 4; direct reader/queue audit and service-free verification: Task 5.
- Explicit failure policy: unsupported legacy v1/future layout, ambiguous alias, mismatched key, incomplete destination and unsafe source sidecars all show unavailable-store recovery rather than an empty plan; a new account with no legacy source legitimately starts empty only after verified Auth and protected scoped open.
- ADR-79's approved shared-plan boundary: copy shared projection and historical events verbatim to each verified member's scoped store, but queue only events originally authored by that account. Do not enqueue a partner's event merely because its history is visible to both members.
